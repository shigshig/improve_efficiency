# Weekly Task Scheduler (週末タスク・スケジュール整理スキル)

毎週末に対話形式で翌週のタスク・スケジュールを最適化し、月曜の朝から迷わず実行できる状態を整えるスキルです。

---

## 1. 起動トリガー

ユーザーから以下のような指示があった際に本スキルを起動します：
- 「来週のスケジュールを整理して」
- 「週末のタスク整理をお願い」
- 「来週の予定を立てたい」
- 「金曜の週次タスクプランニングを開始して」

---

## 2. 厳格スケジューリングルール

本スキルは以下のルールを厳密に遵守してスケジュールを編成します：

1. **午前集中タイム (08:45 〜 12:30)**:
   - 最も思考力・集中力を要する作業を配置する。
   - **複数ステップからなる大きな作業の「最終仕上げ作業」は最重要・最高負荷として午前集中枠に優先配置する**。
2. **午後通常タイム (13:30 〜 17:30)**:
   - 定常業務、ミーティング、連絡・メール対応、中間ドラフト作成を配置する。
   - 昼休憩（12:30 〜 13:30）には業務を配置しない。
3. **30分単位のタスク分解（AIによる文脈適応分解）**:
   - 1時間以上の作業や複数工程のタスクは、**AIが業務文脈・作業内容を読み解き、最適な30分単位のサブタスクに自律分解**します。
   - 分解したサブタスクの中で、最も慎重さや確認を要する最終工程を「仕上げ作業（`is_finishing: true`）」として自動設定します。
4. **定時退社原則 & 期限調整**:
   - 17:30退勤を基準とする。定時枠を超える場合、**MUST以外のタスク（WANT/期限未定）を検出し、翌々週以降への延期（リスケジュール）を提案する**。
   - 期限未定タスクには、工数と空き状況から最適な期日を提案する。
5. **残業時間の予測**:
   - MUSTタスクのみで定時枠を超過する場合に限り、定時以降（17:30〜）の残業枠を算出し、必要残業時間（30分単位）を予測・警告する。
6. **前倒し対応**:
   - 週内に空きバッファがある場合、翌週以降の余裕タスクを前倒し配置する。

詳細なロジックは [scheduling-rules.md](./references/scheduling-rules.md) を参照してください。

## 3. 実行手順（エージェント対話ワークフロー）

### Step 1: 情報収集（タスクと既存予定の確認）
1. ユーザーに来週のタスク・予定の取得方法を確認します：
   - **Microsoft 365 連携**: `python .agents/skills/weekly-task-scheduler/scripts/m365_client.py --get-events --get-tasks`
   - **フォールバック入力**: `templates/task_input_fallback.md` を案内し、チャット入力またはファイル編集を促す。
2. 収集する情報:
   - 翌週の開始日（月曜日の日付）
   - 固定会議・予定（日時・タイトル）
   - タスク一覧（タスク名、見積工数、MUST/WANT区分、期限、集中度）

### Step 2: AIによる文脈適応型のタスク分解
1時間以上のタスクや複数工程のタスクについて、AIがタスクの内容（業務文脈）を分析し、最適な30分単位のサブタスクリストを作成します：
- 例：「四半期営業報告書の作成 (2.0h)」
  - [1] 営業数値の抽出と集計 (30m, 集中)
  - [2] 未達要因と競合動向の分析 (30m, 集中)
  - [3] 来期施策スライドのドラフト化 (30m, 通常)
  - [4] 【仕上げ作業・集中】役員向けサマリー推敲・最終チェック (30m, 集中・仕上げフラグ)

### Step 3: 最適化エンジンの実行
AIが分解したサブタスク一覧と固定会議情報を入力JSONにまとめ、最適化スクリプトを実行してタイムスロットへ最適配置します：

```powershell
python .agents/skills/weekly-task-scheduler/scripts/schedule_optimizer.py --input <tasks_json_path> --output plans/weekly_plan.md
```
※スクリプトが利用できない環境でも、`references/scheduling-rules.md` に記載のアルゴリズムに従ってLLMが直接スロット配置・残業計算を行います。

### Step 4: スケジュール案・調整提案のユーザー提示
以下のサマリーをユーザーに提示し、確認・承認を求めます：
- **工数＆稼働サマリー**: 総工数、会議時間、空きバッファ時間、残業予測（ある場合）
- **期限調整（リスケジュール）提案**: WANTタスクの延期提案、期限未定タスクの期限設定
- **前倒し配置タスク**: 空き枠に組み込んだタスク
- **週間タイムテーブル**: 08:45〜17:30の30分刻みタイムテーブル
- **日別アクションリスト**: 朝一番に確認できるTo-Do形式

### Step 5: ユーザー承認と反映
ユーザーから承認または微調整指示を受けたら：
1. **確定版の保存**: `plans/YYYY-Wxx.md` に確定計画を保存。
2. **外部連携の実行**:
   - Outlook カレンダーへのイベント一括登録（または `.ics` ファイルの提供）
   - Microsoft To Do の期日更新
