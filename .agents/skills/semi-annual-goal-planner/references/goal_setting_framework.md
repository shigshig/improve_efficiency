# 半期目標設定フレームワーク基準 (Goal Setting Framework)

本ドキュメントは、半期目標設定エージェントが目標ドラフトを生成および評価する際に準拠すべき基準・ガイドラインです。

---

## 1. 3つの必須観点と定義

本スキルで策定する目標は、必ず以下の3観点を網羅します。

```
├── 1. 担当チームでの売上貢献  : チームの収益目標達成や案件推進に直接・間接に寄与する
├── 2. 人材育成                : 後輩・チームメンバーの成長と組織の持続的生産性を高める
└── 3. 自社の事業貢献          : 自組織・全社のナレッジ共有、業務効率化、事業成長を牽引する
```

### ① 担当チームでの売上貢献
- **目的**: チームの予算達成、利益率向上、優良顧客との関係深化。
- **対象となる取り組み例**:
  - 担当案件の確実な納品（検収完了による売上確定）
  - 既存顧客への追加提案・アップセル/クロスセルの獲得
  - 新規引き合いに対する提案書作成・コンペ勝率向上
  - 開発工数の適正化・手戻り削減によるプロジェクト利益率（粗利率）の改善
  - 受注前PoCの推進による大型案件化支援
- **定量化の切り口**: 受注金額（万円）、追加売上額、納期遵守率（%）、提案件数、粗利率改善幅（pt）。

### ② 人材育成
- **目的**: 属人化の解消、チームの総合力向上、後進の自立促進。
- **対象となる取り組み例**:
  - 特定メンバー（後輩・新メンバー）へのOJT・技術指導
  - 業務マニュアル・チェックリストの整備による独り立ち支援
  - コードレビュー・設計レビューを通じた品質担保と指導
  - チーム内勉強会の企画・定期開催
- **定量化の切り口**:
  - 指導対象者の自立レベル（「〇〇業務を単独で遂行可能にする」）
  - 指導工数の削減率（「初期30時間/月 → 最終的に5時間/月に短縮」）
  - レビュー指摘数・差し戻し率の低減（「差し戻し率 15%以下」）
  - 開催回数・カリキュラム完了数（「全〇回のワークショップ実施」）

### ③ 自社の事業貢献
- **目的**: 担当チームの枠を超えた全社的インパクト、ナレッジの資産化、組織力の底上げ。
- **対象となる取り組み例**:
  - 業務自動化ツール、AIプロンプト/スキルの開発および社内展開
  - 社内共通コンポーネント・フレームワークの整備
  - 全社ナレッジベース（Notion, Confluence等）への体系的なドキュメント蓄積
  - 新卒・中途採用における技術面談、採用イベント登壇、技術ブログ執筆
  - 新規事業・新ソリューションの検証（PoC）
- **定量化の切り口**:
  - ツール導入による全社削減工数（「月間計〇〇時間の削減」）
  - 社内展開・利用ユーザー数（「〇部門・〇名以上が利用」）
  - 技術記事執筆数（「〇本公開、PV数〇〇」）
  - 採用面談実施数（「〇名対応」）

## 2. 目標設定のSMART原則

すべての目標項目は、以下のSMART基準を厳格に満たす必要があります。

| 原則 | チェック項目 | NG例 | OK例 |
| :--- | :--- | :--- | :--- |
| **S** (Specific: 具体的) | 誰が読んでも実行内容がイメージできるか | 「案件を頑張って進める」 | 「案件Aの要件定義から基本設計までをリードし、仕様凍結を完了させる」 |
| **M** (Measurable: 測定可能) | 達成・未達が第三者に判定できる数値が含まれているか | 「売上にできるだけ貢献する」 | 「担当案件において追加提案を2件実施し、追加売上300万円を受注する」 |
| **A** (Achievable: 達成可能) | 役職要件と現状実力から見て適正なストレッチ度か | 現状のキャパシティの3倍を前提とした計画 | 通常業務の効率化で捻出できる週2〜3時間を充当する設計 |
| **R** (Relevant: 関連性) | 役職定義、前期課題、チーム目標に直結しているか | 会社の事業と関係のない自己満足の学習 | 役職昇格要件である「後進育成」を満たすためのOJT計画 |
| **T** (Time-bound: 期限明確) | 半期末だけでなく中間マイルストーンが明記されているか | 「半期中になんとかする」 | 「第1Q末（〇月末）にβ版公開、第2Q末（〇月末）に社内展開完了」 |

## 3. 定量化（KPI）パターンの変換ガイド

定性的な目標になりがちな項目を、客観的な数値に落とし込むための変換パターン集です。

### パターンA: 「率」・「比率」に変換する
- 「バグを減らす」 → 「単体テスト網羅率 85%以上、結合テストでのバグ検出密度 〇件/KLoC以下」
- 「レビューをしっかりやる」 → 「一次レビュー差し戻し率 10%以内、レビューリードタイム 24時間以内達成率 95%」

### パターンB: 「件数」・「回数」に変換する
- 「積極的にナレッジ共有する」 → 「Tipsドキュメントを月2本（半期計12本）作成・社内公開」
- 「提案活動を強化する」 → 「新規/追加の顧客提案書を半期で3件作成し提案実施」

### パターンC: 「時間」・「工数削減」に変換する
- 「作業を効率化する」 → 「自動化スクリプトを導入し、週次集計作業を2時間/週 → 15分/週に削減（月計7時間削減）」
- 「問い合わせ対応を早くする」 → 「一次回答までの所要時間を平均2営業日以内とする」

### パターンD: 「状態移行（マイルストーン完了）」に変換する
- 「後輩を育てる」 → 「〇〇業務において、上長同席なしで一人で顧客折衝・要件定義を完了できる状態（判定テスト合格または初回単独遂行）」
- 「新技術をキャッチアップする」 → 「〇〇認定資格の取得、および自社プロジェクトへの適用可否評価レポート（A4 3枚）の提出」

## 4. 昇格基準（役職要件）との整合性チェック

エージェントは目標ドラフトを作成する際、必ず以下のチェックを実施します：
1. **上位役職の要件を満たす行動が含まれているか**:
   - 現グレードの標準業務をこなすだけでは「現状維持」の評価にしかならない。
   - 次の役職・グレードの定義（例: 「チーム全体の技術リードができる」「自立して複数案件を統括できる」など）に踏み込んだチャレンジが含まれているか。
2. **前期のマイナス評価・課題が解消される手立てになっているか**:
   - 前期に「スケジュールの遅延傾向」「報連相の不足」「属人化」が指摘されていた場合、その是正が達成手段（Action）に組み込まれているか。
